- F1 (persistence and characters): **persistent characters, authenticated sessions and double-entry economy over PostgreSQL**. Canonical UUID identifiers unify domain types and database columns (`packages/core/src/ids.ts`); the new `@gta6-rp/persistence` package provides the driver-neutral SQL session (production `pg` pool plus the embedded-PostgreSQL verification engine), the migration runner and the PostgreSQL repositories for accounts, sessions, characters, financial accounts and the ledger. Migration `0002` is additive only: the sessions table (token hashes, server-granted capabilities, expiry, revocation), the idempotency fingerprint column, the unique account-per-owner-kind index, the reserved double-entry treasury rows and a deferred constraint trigger that rejects unbalanced ledger transactions written even by direct SQL. The ledger posts atomically (idempotency-key replays return the original receipt, different fingerprints under the same key fail as conflicts, `FOR UPDATE` row locks serialize concurrent writers and balances are re-derived from the entries before commit); balances are always the sum of the entries — there is no mutable balance column.
- F1 verification: characters, sessions and ledger contracts run identically over the deterministic in-memory stores and the embedded PostgreSQL engine; restart suites prove a character created in one run is recovered byte-for-byte in the next and that replayed commands deduplicate instead of double-crediting; concurrency suites race idempotency keys and overdrafts and assert no duplicates, no negative balances and money conservation. `tests/postgres-live.test.ts` runs the same acceptance against a real server with genuinely concurrent connections when `DATABASE_URL` is a `postgres://` URL, the prepared `ci(f1)` follow-up commit lands the workflow change that provisions a `postgres:17` service for the hosted run. The default local gate needs no server; embedded test clusters are cleaned up after each run.
