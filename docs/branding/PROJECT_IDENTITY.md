# Project Identity and Asset Policy

**State:** ACTIVE

This repository represents an independent technical project preparing our own future roleplay server/community.

The project should look deliberate and original without implying that it is an official Rockstar Games, Take-Two Interactive, GTA VI or Cfx.re product.

## Identity principles

- use an original community/server name when the final public identity is chosen;
- use original logomarks, typography systems and visual treatments for project-facing branding;
- avoid visual presentation that could reasonably be mistaken for an official Rockstar Games product or service;
- keep technical naming functional inside the repository until the final community identity has been selected;
- do not let branding decisions dictate runtime architecture.

## Official game material

Official logos, screenshots, key art, character artwork and other proprietary game assets may be useful as external design or research references.

They should not be committed into this repository merely to decorate the README or documentation unless there is a clear right and project reason to redistribute them.

For repository-facing identity, prefer project-owned assets.

## Future custom assets

When original branding is created, keep assets organized by purpose rather than as an unstructured image dump.

Suggested structure:

```text
assets/
  brand/
    source/        editable project-owned sources
    export/        approved SVG/PNG exports
  docs/            diagrams and documentation visuals
```

Do not commit generated caches, redundant export sizes or licensed source material that cannot be redistributed.

## Documentation and footer style

Project documents should end naturally when their content is complete.

Do not add:

- “generated by” notices;
- assistant/model attribution;
- generic “made with AI” language;
- synthetic signatures;
- decorative legal boilerplate copied onto every page;
- repeated footers that make internal documentation look machine-produced.

Where a legal or affiliation note is genuinely useful, write it once in the appropriate repository-level location using project-specific language.

## Naming discipline

Until a final community identity exists:

- repository/package names may remain technical and descriptive;
- do not invent a public-facing GTA VI server brand simply to fill placeholders;
- environment, service and database names should describe their technical purpose;
- naming decisions that affect players or public identity should be documented before they propagate into code and data schemas.

## Affiliation statement

The current project position is simple: independent technical preparation, not an official Rockstar Games, Take-Two Interactive or Cfx.re product.

That distinction should remain clear without turning every document into a disclaimer page.
