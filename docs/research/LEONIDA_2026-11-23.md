## Why this matters to our server

Leonida is a third-party project attempting to run an Xbox Series build of GTA VI on Windows through a native x86-64 PE loader, Xbox service shims and translation of RDNA2 graphics programs to SPIR-V/Vulkan. It also provides tools for examining package assets and a local world viewer.

The repository is a potentially useful *technical reference*, not an RP framework, a server runtime or an endorsed development kit. It cannot supply the authorized client/server integration contract required by our project.

This record captures what upstream publishes as of the review date. It does not independently reproduce the upstream benchmarks or validate behavior against an executable.

## What is useful now

1. **World-planning workflow design:** study how an offline viewer organizes spatial layers, models and navigation information. Develop our own mock map using synthetic, project-owned geometry and coordinates.
2. **Asset-format awareness:** learn the *categories* of data a future authorized editor might need (static geometry, interior metadata, navmeshes, interaction points). Do not commit extracted game data, conversion results or proprietary identifiers.
3. **Compatibility testing practice:** borrow the ideas of deterministic fixtures, explicit test environments, bounded status reporting and per-driver regression records. Implement tests against our own simulator contracts only.
4. **Operational feasibility assessment:** record storage, GPU and tooling burdens as research costs, not runtime requirements for our RP server.

None of these tasks needs to call Leonida or copy its source code into this monorepo.

## Explicitly out of scope

- Building or operating an unauthorized GTA VI multiplayer server or client.
- Treating the Xbox build, its package layout or its internal APIs as a GTA VI community-server API.
- Integrating Leonida's PE loader, graphical shims, shader translator or viewer as a production dependency.
- Obtaining console packages, keys or protected content; bypassing encryption or access controls.
- Committing, sharing or uploading game executables, archives, derived shaders, models, textures, audio, navigation data, extracted location lists or outputs of local extraction.
- Inferring exact gameplay coordinates, spawn APIs, doors, entities or network synchronization semantics from an offline viewer.
- Copying GPL-covered implementation code or other third-party code without a separate license and dependency review.

## Work we can do without GTA VI runtime access

- Specify an **internal RP location-planning workflow** using original or synthetic maps.
- Design a conceptual location catalog: project-owned IDs, labels, intended RP use, review state and source/provenance notes. Coordinate-system details remain unspecified until legitimately documented.
- Prototype staff workflows for proposing, reviewing and approving locations in the simulator; approval must not create a live game entity.
- Test server-side authorization and audit of proposed changes.
- Keep prototype fixtures wholly synthetic and independently created.

No new data schema, package dependency, production map or GTA VI adapter API is approved by this assessment. A substantive new cross-module contract needs normal design review.

## Evidence and integration gates

**Evidence classification:** upstream repository content is a *third-party public observation*, not first-party `CONFIRMED` evidence under [our research protocol](./RESEARCH_PROTOCOL.md). Its possible relevance to our planning is `INFERENCE`. No GTA VI `RT-*` requirement changes state.

| Gate | Required evidence/action | Current outcome |
| --- | --- | --- |
| Study upstream approaches | Read public code/docs without importing data | Permitted research |
| Use source code in our repository | Source/license audit, necessity, version pin and approval | Not approved |
| Load extracted game data into our tools | Provenance, rights, permitted use, isolation and human review | Not approved |
| Implement GTA VI adapter | GTA VI-specific first-party authorization and implementable API; requirements, ADR and conformance tests | **BLOCKED** |
| Host a live RP server | Authorized runtime, security and policy/operational clearance | **BLOCKED** |

See [third-party artifact policy](../operations/THIRD_PARTY_ARTIFACT_POLICY.md), [runtime requirements](../server/RUNTIME_REQUIREMENTS.md) and [P5 roadmap gate](../roadmap/ROADMAP.md).

## Reassessment triggers

Revisit this assessment only when:

- Leonida publishes a reproducible real-game boot demonstration with enough detail to validate it;
- material upstream behavior or licensing changes;
- a legitimate first-party GTA VI developer/community-server path is publicly documented;
- our own server-planning requirements justify a small, isolated tool experiment.

A successful Leonida boot would update this *technical assessment*, not automatically unlock our GTA VI runtime gate.
